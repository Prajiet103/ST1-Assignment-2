# Part A - Understand the Problem

## Q1. What data must be stored?
The system needs to be able to store patient information. Such as names date of\
birth and other important details which the doctors will need to know to look up\
medical records. Other data types also include the doctors names and the\
appointment time for the patients to see their doctors.

## Q2. What functions might be useful?
A function like patient notes may be useful, if any patient information needs \
to be passed on to the receptionists from the doctors or vice versa then this function would\
make things quite seamless. Another feature that might be quite useful is a self check in feature, I\
believe this feature would be especially useful during busy periods of the year when lots of people\
are getting checkups it would help the entire clinic run smoother in general.

## Q3. What could go wrong?
Depending on the systems structure you could see some issues of patients being assigned to the\
wrong doctor. For example two patients might have an appointment at the same time with\
different doctors, But the system has assigned them the wrong doctors. Since their timeslots where\
in the same position the system made an error.
